# Инструкции для кодовых агентов

Этот файл действует для всего репозитория StackMIREA. Общайтесь с пользователем и оформляйте новую проектную документацию на русском языке.

## Цель проекта

StackMIREA — статическая документационная платформа на Next.js 14, React 18 и TypeScript. Основной пользовательский контент находится в `docs/`, а сайт публикуется в GitHub Pages.

## Карта репозитория

- `app/` — маршруты App Router и страницы;
- `components/` — интерфейс, layout и MDX-компоненты;
- `docs/` — канонические исходники учебных материалов;
- `lib/` — manifest, навигация, поиск и общие функции;
- `scripts/` — сборка и проверка контента;
- `resources/` — датасеты и дополнительные материалы;
- `public/` — публичные ассеты и сгенерированный поисковый индекс;
- `.github/` — шаблоны и CI/CD.

Каталог `content/` не является источником для текущего pipeline. Не синхронизируйте его с `docs/` и не переносите туда изменения без отдельной задачи.

## Правила изменений

1. Сначала прочитайте ближайший связанный код и проверьте `git status`.
2. Не перезаписывайте и не удаляйте посторонние изменения пользователя.
3. Делайте минимальный связный diff и соблюдайте существующий стиль.
4. Для поиска используйте `rg` или `rg --files`.
5. Не добавляйте зависимости без явной необходимости.
6. Не редактируйте вручную `.cache/content-manifest.json`, `.cache/content-report.*` и `public/search-index.json`.
7. Не коммитьте `out/`, `.next/`, локальные логи, секреты и временные файлы.
8. Добавляйте заметные пользовательские и инфраструктурные изменения в раздел «Не выпущено» файла `CHANGELOG.md`.

## Контент

- Создавайте и обновляйте материалы в `docs/<track>/`.
- Сохраняйте frontmatter-поля `title`, `description`, `author` и `order` либо `sidebar_position`.
- Для нового трека обновляйте `lib/tracks.json` и добавляйте `docs/<track>/index.mdx`.
- Указывайте язык у code fence, используйте относительные ссылки и проверяйте якоря.
- Файлы практик и датасеты размещайте в `resources/`, если их нужно скачать отдельно.
- После изменения контента запускайте `npm run quality`; команда сама пересоберёт manifest и поисковый индекс.

## Код

- Сохраняйте строгую типизацию и не используйте `any` без обоснования.
- Предпочитайте серверные компоненты; добавляйте `"use client"` только для интерактивности или browser API.
- Используйте существующие UI-компоненты и дизайн-токены до создания новых абстракций.
- Учитывайте статический экспорт и production `basePath` `/StackMIREA`.
- Для внутренней навигации используйте `next/link`, а для изображений — `next/image`, если это совместимо со статическим экспортом.
- Изменения в поиске, manifest или навигации сопровождайте тестами в ближайшем `__tests__`.

## Проверки

Выбирайте проверки по области изменения:

| Изменение | Обязательные команды |
| --- | --- |
| Только Markdown/community-файлы | Проверить ссылки и diff вручную |
| Материалы в `docs/` | `npm run quality`, `npm test` |
| TypeScript или UI | `npm run lint`, `npm run typecheck`, `npm test` |
| Pipeline, поиск или manifest | `npm run quality`, `npm test`, `npm run typecheck` |
| Изменение сборки или перед релизом | Все проверки выше и `npm run build` |

Если команда завершилась ошибкой, определите, вызвана ли она текущим diff. Не скрывайте ошибку и не ослабляйте проверку ради зелёного результата.

## Готовность задачи

Перед завершением:

- просмотрите `git diff --check` и `git status --short`;
- убедитесь, что изменения соответствуют запросу;
- перечислите изменённые области и выполненные проверки;
- отдельно сообщите о невыполненных проверках, известных ограничениях или побочных изменениях сгенерированных файлов.
